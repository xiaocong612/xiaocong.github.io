这次更新主要围绕博客首页的阅读体验、内容维护方式和文章代码块展开。整体保留了原有的中文个人博客定位，继续使用 Hexo 和 GitHub Pages 发布，同时把首页改造成更完整的自然风格主视觉，并让日常更新更容易维护。

## 首页主视觉

首页现在使用原创的山湖图片作为首屏背景。图片会覆盖完整的首屏区域，站点名称、小标题和循环文案居中显示，底部通过渐隐过渡自然连接到下面的文章内容和网点背景，避免图片与正文之间出现突兀的硬切换。

主视觉下方保留精选文章、最近更新、标签、分类和归档入口。各个内容板块使用半透明黑色背景、圆角和轻微模糊效果，在保持层次的同时不会遮挡文章信息。鼠标移入板块时，边缘会以平滑过渡的方式显示蓝色高亮和光晕。

背景网点使用原生 Canvas 绘制。桌面端和移动端采用不同的点数量，点与点之间只连接一部分邻近节点，并使用缓慢的出现、消失和透明度变化，让背景保持轻量的呼吸感。系统开启“减少动态效果”时，相关动画会自动降级。

## 文案与名句

首页文案和名句没有写死在模板中，而是集中存放在 `source/_data/home.yml`。首页会从文案库中逐字显示句子，停留一段时间后再逐字删除并切换到下一句。脚本按 Unicode 字素处理，因此中文、表情符号和组合字符不会在中间被错误拆开。

名句区域采用磨砂玻璃样式，右侧的按钮可以随机切换下一条内容，并避免连续显示同一句。名句框使用完整内容预留高度，切换时不会让页面下方产生跳动。没有启用脚本时，首条文案和名句仍然可以直接阅读。

## Decap CMS 管理

后台新增了“首页内容”集合，位置在 Decap CMS 的“首页内容 → 文案与名句”。这里可以编辑首页小标题、打字文案库和哲言名句库，也可以对列表进行新增、删除和排序。

后台保存的内容会写回 `source/_data/home.yml`，随后由 Hexo 在构建阶段生成静态页面。也就是说，后台编辑不会绕过构建流程直接修改线上页面；完成发布并等待 GitHub Actions 部署后，更新才会出现在正式站点上。这种方式与文章的 Markdown 写作流程保持一致，也便于通过 Git 历史追踪每次修改。

## 代码块改造

文章中的 fenced Markdown 代码块现在保留为标准的 `<pre><code>` 结构，先保证没有脚本时也能正常阅读。在浏览器端加载本地的 highlight.js 后，代码块会渐进增强为 Atom One Dark 风格，并提供语言标识、语法颜色、行号、复制和折叠能力。

代码资源放在主题内部，不依赖第三方 CDN。未识别的语言会保留原始代码内容，移动端支持横向滚动，剪贴板不可用时也不会影响文章阅读。这样既保留了 Markdown 的可移植性，也改善了长代码在文章页中的浏览体验。

## 安全与响应式处理

首页模板会对后台输入进行 HTML 转义，前端更新内容时只写入文本节点，不把句库内容当作 HTML 执行。文章 Markdown 仍然经过安全净化，搜索结果也只接受站内路径。

布局采用响应式断点适配桌面和移动设备，首屏高度使用稳定的视口约束，文案和名句框允许自然换行，页面不会因为动态文字长度改变而产生横向溢出。当前本地验收已经覆盖桌面视口和 390px 手机视口，自动化测试覆盖模板安全、打字状态、名句切换、网点密度、代码块增强和站点构建。

## 发布方式

本次更新仍然沿用 GitHub Actions 发布流程。日常可以直接编辑 `source/_posts` 中的 Markdown 文件，或通过后台管理文章和首页内容；检查通过后提交到 `main` 分支，GitHub Actions 会自动完成 Hexo 构建并发布到 GitHub Pages。
